# Triage

把项目 issue tracker 上的议题推进一个小型 triage roles 状态机。

分诊期间发布到 issue tracker 的每条 comment 或 issue **都必须**以这个 disclaimer 开头：

```
> *This was generated by AI during triage.*
```

## 参考文档

- [AGENT-BRIEF.md](AGENT-BRIEF.md)：如何写 durable agent briefs
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)：`.out-of-scope/` knowledge base 如何工作

## Roles

两个 **category** roles：

- `bug`：已有东西坏了
- `enhancement`：新功能或改进

五个 **state** roles：

- `needs-triage`：maintainer 需要评估
- `needs-info`：等待 reporter 补充信息
- `ready-for-agent`：已经完整说明，AFK agent 可以接手
- `ready-for-human`：需要人类实现
- `wontfix`：不会处理

每个已分诊 issue 都应该恰好有一个 category role 和一个 state role。如果 state roles 冲突，先标出来并询问 maintainer，再做其它动作。

这些是 canonical role names；issue tracker 里实际使用的 label 字符串可能不同。映射应该已经提供给你；如果没有，先运行 `/setup-matt-pocock-skills`。

状态转移：未标记 issue 通常先进入 `needs-triage`；之后转到 `needs-info`、`ready-for-agent`、`ready-for-human` 或 `wontfix`。`needs-info` 在 reporter 回复后回到 `needs-triage`。Maintainer 可以随时覆盖；看起来异常的转移要先标出并询问。

## 调用方式

Maintainer 调用 `/triage`，并用自然语言描述他们想做什么。理解请求并执行。示例：

- "Show me anything that needs my attention"
- "Let's look at #42"
- "Move #42 to ready-for-agent"
- "What's ready for agents to pick up?"

## 展示需要关注的议题

查询 issue tracker，按 oldest first 展示三个桶：

1. **Unlabeled**：从未分诊。
2. **`needs-triage`**：正在评估。
3. **`needs-info` with reporter activity since the last triage notes**：reporter 已有新活动，需要重新评估。

展示每个桶的数量，并为每个 issue 给一行摘要。让 maintainer 选择。

## 分诊指定 issue

1. **收集上下文。** 阅读完整 issue（body、comments、labels、reporter、dates）。解析之前的 triage notes，避免重复询问已解决问题。使用项目领域 glossary 探索代码库，并尊重相关区域的 ADR。读取 `.out-of-scope/*.md`，找出是否有相似的历史拒绝。

2. **给出建议。** 告诉 maintainer 你推荐的 category 和 state，给出理由，并提供与该 issue 相关的简短代码库摘要。等待指示。

3. **复现（仅 bugs）。** 在任何追问之前，先尝试复现：阅读 reporter 的步骤，追踪相关代码，运行测试或命令。报告发生了什么：成功复现及代码路径、复现失败，或细节不足（强 `needs-info` 信号）。已确认复现会让 agent brief 强很多。

4. **追问（如需要）。** 如果 issue 需要补充细节，运行 `/grill-with-docs` session。

5. **应用结果：**
   - `ready-for-agent`：发布 agent brief comment（[AGENT-BRIEF.md](AGENT-BRIEF.md)）。
   - `ready-for-human`：使用和 agent brief 相同结构，但说明为什么不能委托（judgment calls、external access、design decisions、manual testing）。
   - `needs-info`：发布 triage notes（模板见下）。
   - `wontfix`（bug）：礼貌解释，然后关闭。
   - `wontfix`（enhancement）：写入 `.out-of-scope/`，在 comment 中链接它，然后关闭（[OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)）。
   - `needs-triage`：应用该 role。如果已有部分进展，可以选择性评论。

## 快速状态覆盖

如果 maintainer 说 “move #42 to ready-for-agent”，信任他们并直接应用 role。确认你即将做什么（role changes、comment、close），然后执行。跳过追问。如果没有经过追问就移动到 `ready-for-agent`，询问是否要写 agent brief。

## Needs-info template

```markdown
## Triage Notes

**What we've established so far:**

- point 1
- point 2

**What we still need from you (@reporter):**

- question 1
- question 2
```

把追问中已经解决的所有内容都写进 “established so far”，避免工作丢失。问题必须具体、可执行，不要写 “please provide more info”。

## 恢复之前的分诊会话

如果 issue 上已有 triage notes，先读取它们，检查 reporter 是否回答了未解决问题，并在继续前展示更新后的情况。不要重复询问已解决问题。
